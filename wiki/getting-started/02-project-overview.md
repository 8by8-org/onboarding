# Project Overview

Let's open this project in the code editor we recommend, 
[VSCode](https://code.visualstudio.com/), so we can examine the project 
structure. Projects will vary somewhat in terms of how they are organized, but 
because we use similar tools to build many of our applications, reviewing this 
project will still give you a great sense of what you can expect to find where 
in most of our repositories.

Open a terminal and navigate into the root directory of this project. Execute 
the following command:

```
code .
```

This will open this project in VSCode.

## Files

### .env.example

This file contains an example `.env` file. Such files can be used in TypeScript 
projects to contain externalized configuration values. The `.env.example` file 
serves to illustrate which environment variables you must configure in order 
to run the project, but it should never be edited directly. Instead, you will 
create a `.env` file in the root directory of the project, copy the contents of 
`.env.example` into this file, and then add actual environment variable values 
to `.env`.

### .gitignore

This file includes a list of files and directories that should not be committed 
to source control. The `.env` file mentioned in the previous section is always 
added to this file because we never want to commit its contents to source 
control; the values of some environment variables will likely be sensitive 
in nature. 

Other contents of this file typically include `node_modules/` which includes 
all of the project's dependencies (this folder is automatically created and 
managed by [npm](https://www.npmjs.com/)), `.DS_Store` (a hidden file that is 
generated by the macOS Finder when it accesses a directory), IDE-specific config 
files (`.vscode`, `.idea`)—if committed, these can sometimes leak secrets 
through run configuration settings, and `coverage/`, which contains unit test 
coverage reports.

### .npmrc

A configuration file for npm. In this project, you will find a minimal example 
with only `min-release-age` set.

### package-lock.json

Contains a comprehensive of all the packages upon which the project depends, 
with exact version numbers. The `npm ci` command, which we use to install 
dependencies in our CI/CD pipelines, uses this file as an authoritative list 
of packages to download. We do not typically edit this file manually.

### package.json

Contains project details such as name, version, author, and a list of 
dependencies. The `npm install` command reads dependencies from this file.

### README.md

A high-level overview of the project written in [markdown](https://en.wikipedia.org/wiki/Markdown). This is displayed on the project's landing page on Github. 

### tsconfig.json

Contains configuration options for TypeScript.

## Directories

### .github 

This directory contains things like markdown templates for pull request 
descriptions, and 
[Github Actions workflow](https://docs.github.com/en/actions/concepts/workflows-and-actions/workflows) definitions written in 
[YAML](https://yaml.org/).

### assets

In this project, this is where we keep images and other assets.

### src

The source code for the project. Unit tests are also included in this directory.
As part of the onboarding process, you will author code and tests in this 
directory.

### wiki

Markdown files that are automatically uploaded to the project Wiki with 
a Github Actions workflow. You will edit one of these as part of the 
onboarding process.
